## Engineering gates before one real-bank pilot

1. **Done:** A separate First Platypus Bank Sandbox Item using Plaid's `user_transactions_dynamic` test user received `/transactions/refresh`, a signed `SYNC_UPDATES_AVAILABLE` webhook, and new transactions in Flow. It was disconnected afterward. Automated checks cover an invalid signature, an expired signature, a Plaid outage, and a database failure. Confirm the same failure behavior against the deployed function before a real pilot. Do not print access tokens or transaction bodies in logs.
2. Test an unhealthy Sandbox Item through Link update mode. Verify that Flow tells the user to reconnect, resumes sync afterward, and that disconnect calls `/item/remove`. Also test a failed account deletion with a disposable Sandbox user.
3. Add handling for Plaid Item warnings such as `PENDING_DISCONNECT` and `PENDING_EXPIRATION`, and complete the mobile OAuth return flow. Register the production redirect URI in Plaid before enabling real banks. A desktop-only pilot can be scoped separately, but unsupported mobile flows must be clearly excluded.
4. Pin or self-host third-party browser scripts, add a reviewed Content Security Policy, and review the browser's offline financial-data copy and sign-out behavior. Confirm no secret or access token appears in browser files, backups, responses, or logs. Have an independent security reviewer check the server functions, RLS, data deletion, and cross-user access.
5. Set up monitoring for failed webhook deliveries, function errors, failed syncs, and sign-in mail delivery. Configure reliable email delivery, recovery/backups, and abuse protection in Supabase. Verify restore and incident response with test data. Supabase says downloadable database backups are unavailable on its Free plan; a Flow JSON export protects the visible budget data but does not restore a Plaid connection or its server-side access token.

## Private pilot deployment order

The pilot branch is **not** a real-bank launch. It defaults to Sandbox until the server has both `PLAID_PILOT_ENABLED=true` and `PLAID_PILOT_USER_ID` equal to Dax's Supabase Auth user ID. No browser file contains a Plaid secret. When enabled, only that user can create a Production Item; all existing Items retain their original Sandbox environment. A database index limits the pilot to one Production Item for that user.

1. Export Flow's current data and arrange a database recovery method appropriate for the Supabase plan before changing the live schema. Run [the additive environment migration](../supabase/2026-10-17-plaid-environments.sql) and [atomic disconnect migration](../supabase/2026-10-17-atomic-bank-disconnect.sql). The first labels existing Items `sandbox`; the second removes a disconnected bank and its saved Flow transactions together so a webhook cannot restore them during disconnect.
2. Deploy the updated Sandbox `plaid-webhook` function, then the separate `plaid-production-webhook` function with JWT gateway verification **off**. Keep JWT verification **on** for the signed-in `plaid` function. The production webhook verifies Plaid's signature with the Production key and touches only Production Items.
3. Set the Production secret in Supabase Edge Function secrets as `PLAID_PRODUCTION_SECRET`; keep the existing `PLAID_SANDBOX_SECRET` separate. Set `PLAID_PILOT_USER_ID` to Dax's Auth user ID. Leave `PLAID_PILOT_ENABLED` unset or `false` while deploying the updated `plaid` function and website. Do not put secrets in SQL, Git, chat, or browser code.
4. Confirm the Sandbox Item still lists and syncs, and confirm a non-pilot user still receives Sandbox Link. Review RLS, sign-in, data export, device copy, disconnect, deletion, and function logs. Arrange an independent security review before enabling real data. Dax must back up and disconnect the existing First Platypus test bank before a Production Link token is available; Flow will not combine its fake transactions with Mountain America data.
5. Once the owner has reviewed the pilot, set `PLAID_PILOT_ENABLED=true`. Only Dax's signed-in account will receive a Production Link token. Dax completes Mountain America authentication directly in Plaid/at the bank. Verify the first sync, a later webhook update, reconnect, disconnect, and data deletion. Disable the flag again if the pilot must stop; existing Production Items remain reachable for sync and removal.

For a desktop browser pilot, Plaid says OAuth usually works without a redirect URI, but some banks require the team's app profile and security questionnaire. Mobile web and embedded browsers remain outside this pilot until the redirect return flow is implemented and tested. Never change to a paid plan or submit verification on behalf of the account owner.
